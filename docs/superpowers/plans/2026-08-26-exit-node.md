**Goal:** `ddns up --exit-node` — full-tunnel visitor client: TUN + smoltcp on the visitor device, flows carried over the P2P data channel to an opt-in exit bridge on the client machine.

**Architecture:** Visitor TUN (1384 MTU) → smoltcp user-space stack terminates TCP/UDP flows → flows ride the existing `REQ`/`RESP`/`DATA`/`CLOSE` framing over an `"exit"`-labeled data channel (REQ payload carries the `host:port\0` destination) → the exit bridge (client side, `--allow-exit` opt-in) dials real sockets. DNS proxied through the tunnel; kill-switch + route exceptions guard leaks.

**Tech Stack:** `tun` crate (wintun//dev/net/tun), `smoltcp`, `rtnetlink` (Linux routes), `netsh`/`iptables` command generation (Windows/Linux kill switch), existing webrtc-rs framing. New deps: `tun`, `smoltcp`, `rtnetlink`.

**Spec:** `docs/superpowers/specs/2026-08-26-exit-node-design.md`

## Global Constraints

- `want_exit` defaults **false** everywhere (serde default; CLI flag opt-in).
- Exit bridge refuses loopback/link-local/RFC1918 destinations by default (`--exit-allow-lan` overrides).
- No new opcodes; `REQ` payload gains an optional destination string (old bridges ignore it — compatibility rule pinned in the spec §2-ADR-3).
- MTU 1384; smoltcp MSS 1344 (IPv6-headroom math per spec §5).
- Platform admin tests (route/firewall) are manual docs checklists, NOT CI.
- TDD every task; fmt + `clippy --workspace --all-targets -D warnings` clean before every commit.
- Version lands at **0.10.0** (final task).
